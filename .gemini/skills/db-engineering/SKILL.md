# DB Engineering Skill

## Capability

此 Skill 提供 Database Engineering capability，包含 DB impact、schema / SQL analysis、data correctness、performance、compatibility、migration / rollback proposal 與 read-only validation evidence。

此 Skill 不改變 Agent 身份，且不得覆蓋根目錄 `GEMINI.md`。

## Configured Alias Only

唯一合法 DB connection source 是 skills-hub 的 `DB_METADATA_CONNECTIONS`。

必須：

1. 使用 `list_connections`。
2. 多組 alias 時使用 `suggest_connection`。
3. 選定明確的 `connection_key`。
4. 在 output 中記錄 selected alias，但不得回傳 connection string。

禁止：

- 從目標專案 `web.config`、`appsettings.json`、程式碼或 transform 擷取 connection string。
- 接受 prompt raw connection string。
- 使用任意 env name、`MSSQL_CONN`、`DB_METADATA_MSSQL_CONN` 或 legacy fallback。
- 預設 production。

沒有可用或明確 alias 時，必須輸出 `Needs More Evidence`。

## Database Mutation Prohibition

任何 Agent、Command 或 Skill 使用本 Skill 時，都不得執行：

- INSERT / UPDATE / DELETE / MERGE / TRUNCATE。
- CREATE / ALTER / DROP。
- Migration、rollback、data fix 或 deployment SQL。
- 未確認為 read-only 的 stored procedure / function。

只允許：

- Read-only metadata query。
- Bounded、明確目的的 read-only validation evidence。
- 產生 migration proposal SQL。
- 產生 rollback proposal SQL。
- 產生 read-only validation SQL。

## Scope

- DB / Data Impact Decision。
- Table、column、index、view、SP、function、trigger、query、report。
- Import / export、sync、batch、data flow。
- Data correctness、transaction、performance、compatibility。
- Migration plan、rollback plan、validation plan。
- DB-assisted dry run evidence。

## Artifact Output Rules

DB Agent 不直接寫檔，必須將 report 與 SQL proposal content 回傳 Main Orchestrator。

Main Orchestrator 使用 `write_sdlc_artifact` category=`db` 建立：

```text
YYYYMMDD_<project>_<feature>_db-impact.md
YYYYMMDD_<project>_<feature>_migration-proposal.sql
YYYYMMDD_<project>_<feature>_rollback-proposal.sql
YYYYMMDD_<project>_<feature>_validation-readonly.sql
```

SQL 檔案必須以以下註解開頭：

```sql
-- PROPOSAL ONLY
-- DO NOT EXECUTE AUTOMATICALLY
-- Generated by skills-hub SDLC
-- Human review and manual execution are required.
```

若 schema、data rule 或 rollback evidence 不足，不得憑空產生可執行 SQL；只提供 DB impact report 與 Open Questions。

## Workflow

1. 判斷 DB / SQL / Data Flow impact。
2. 整理 DB Platform、Hosting、Target System 與 affected objects。
3. 依 configured alias rules 選定 `connection_key`。
4. 只查詢任務直接相關的 read-only metadata。
5. 分析 schema、SQL、data correctness、performance、compatibility、transaction 與 rollback risk。
6. 產生 DB impact report。
7. 資訊足夠時產生 migration、rollback 與 read-only validation SQL proposal content。
8. 回傳 artifact file names 與 content 給 Orchestrator。

## Safety and Limitations

- 預設 read-only。
- 不得直接修改任何 DB environment。
- 不得輸出 connection string、password、token 或敏感資料。
- 不得在 alias、environment、sensitivity、dialect 或 rollback 不明時繼續。
- 不得覆蓋 `GEMINI.md` Change Control、artifact policy、DB isolation 與 mutation prohibition。
